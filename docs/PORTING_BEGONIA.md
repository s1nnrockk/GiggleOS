# Исследование первого порта: Redmi Note 8 Pro (begonia)

## Статус

**Research only — GiggleOS не собрана и не проверена на телефоне.** Пользователь подтвердил коммерческую модель: Xiaomi Redmi Note 8 Pro. Целевое codename для стандартного Redmi Note 8 Pro — `begonia`. Точный номер модели и объём RAM ещё не подтверждены.

## Аппаратная платформа

- SoC: MediaTek Helio G90T (семейство MT6785).
- GPU: Mali-G76 MC4.
- Архитектура: ARM64.
- Варианты памяти и региональные аппаратные варианты необходимо подтвердить по конкретному номеру модели; не угадывать их.

Эти сведения относятся к Redmi Note 8 Pro и не должны смешиваться с Redmi Note 8 (`ginkgo`, Snapdragon 665) или Redmi Note 8 (2021) (`biloba`).

## Состояние upstream

- В актуальном каталоге устройств LineageOS codename `begonia` не значится как официально поддерживаемое устройство.
- Существуют community/unofficial сборки для `begonia`, но наличие таких сборок не означает официальную поддержку и не подтверждает совместимость с GiggleOS.
- Каталоги сторонних ROM можно использовать только как указатель для дальнейшего аудита. Перед использованием любого исходного дерева нужно проверить владельца, историю изменений, лицензию, актуальность, зависимости и точные ревизии.
- Обзор сторонних сборок: https://thecustomrom.com/devices/xiaomi/begonia
- Дополнительный каталог устройства: https://customdroid.info/device/redmi-note-8-pro

## Результат предварительного аудита

Найдены публичные кандидаты device tree, kernel, vendor и firmware для begonia. Обнаружены несовпадение пути kernel checkout между BoardConfig и dependency manifest, разные Android-ветки и неурегулированный статус распространения proprietary blobs. Эти исходники пока нельзя считать согласованным комплектом для сборки. Подробности и точные ревизии зафиксированы в [BEGONIA_SOURCE_AUDIT.md](BEGONIA_SOURCE_AUDIT.md).

## Следующие инженерные задачи

1. Подтвердить точный номер модели и объём RAM в «Настройки → О телефоне → Подробная информация и характеристики».
2. Подтвердить codename `begonia` по системной информации устройства, не изменяя его загрузочные разделы.
3. Выполнить предварительный аудит кандидатов device tree, kernel tree и vendor blobs; см. [отчёт аудита](BEGONIA_SOURCE_AUDIT.md). Кандидаты пока не одобрены для сборки.
4. Зафиксировать версии Android base, manifest, firmware, kernel и всех зависимостей.
5. Проверить лицензии и обязательные уведомления каждого upstream-компонента.
6. Подготовить отдельную конфигурацию продукта GiggleOS для `begonia`.
7. Создать воспроизводимую Linux-сборку и сохранять полные build-логи.
8. Добавить автоматические проверки метаданных и структуры проекта; полноценную сборку AOSP не запускать на обычном CI runner без подтверждённых ресурсов.
9. До любых аппаратных испытаний подготовить документированный план восстановления и проверить сборку на безопасной тестовой инфраструктуре.

## Не делать

- Не использовать конфигурации `ginkgo` или `biloba` для `begonia`.
- Не считать сторонний ROM официальной поддержкой LineageOS.
- Не публиковать ZIP/IMG как установочный релиз GiggleOS до полного аудита и тестирования.
- Не обещать универсальный образ или установку в один клик на неподтверждённых моделях.
