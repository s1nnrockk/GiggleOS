# GiggleOS

**GiggleOS** — проект полноценной Android-based мобильной операционной системы с собственным интерфейсом и системными приложениями.

Цель — общая платформа GiggleOS и отдельные проверенные device-порты для конкретных моделей. Один универсальный образ для всех телефонов технически невозможен.

> **Статус:** раннее проектирование и исследование первого порта. Рабочая прошивка и установочные образы пока не выпущены. CI проверяет метаданные и прототипы; AOSP не собирается.

## Принятые продуктовые решения

- **Интерфейс:** оригинальный стиль GiggleOS в духе следующего поколения iOS: плавные анимации, выразительная типографика, глубина и выборочные стеклянные поверхности. Material 3 не используется как основа дизайна.
- **Первый запуск:** собственный GiggleOS Setup Wizard с приветствием, языком, регионом, Wi-Fi, SIM, переносом данных, защитой экрана блокировки и персонализацией.
- **Системный интерфейс:** нативный прототип быстрых настроек, центра уведомлений с добровольным доступом и системных переходов.
- **Домашний экран:** собственная сетка приложений, док, живые часы, Центр управления и поиск по установленным приложениям.
- **Настройки:** отдельный экран с поиском и разделами подключения, персонализации, уведомлений, безопасности и системы; есть сохраняемые светлая/тёмная темы, три цветовые палитры и четыре обоев для экрана блокировки.
- **Приложения:** собственные приложения GiggleOS плюс цель совместимости с обычными Android APK через Android Framework и ART.
- **Первое устройство:** Xiaomi Redmi Note 8 Pro (begonia).

## Архитектура

- **Основа:** Android Open Source Project (AOSP).
- **Первый device bring-up:** аудит совместимых upstream/community исходных деревьев для выбранного устройства.
- **Низкий уровень:** Linux kernel, HAL, device tree и vendor-компоненты конкретного устройства.
- **Системный опыт:** собственный System UI, Setup Wizard, настройки и приложения.
- **Сборка:** Android build system / Soong и отдельные конфигурации устройств.
- **Проверки:** GitHub Actions проверяет корректность профилей и прототипов. Это не сборка ОС и не создание прошивки.

## Первый целевой телефон

Первый целевой телефон подтверждён пользователем: **Xiaomi Redmi Note 8 Pro**, codename begonia. Точный номер модели и объём RAM ещё предстоит проверить.

Redmi Note 8 Pro использует платформу MediaTek Helio G90T и требует отдельного device-port. Не путать его с Redmi Note 8 (ginkgo, Snapdragon) и Redmi Note 8 (2021) (biloba). Для begonia нельзя автоматически считать официальную поддержку LineageOS доступной: найденные сторонние/community сборки требуют отдельного аудита и не являются сборками GiggleOS.

См. [матрицу поддержки](docs/DEVICE_SUPPORT.md), [исследование порта begonia](docs/PORTING_BEGONIA.md), [план разработки](docs/ROADMAP.md) и [профиль устройства](devices/begonia/device.json).

## Прототипы

Нативный Android-прототип Setup Wizard содержит двенадцать экранов и Rust JNI core для проверки переходов, категорий переноса и SHA-256. Экран блокировки использует системный Android Keyguard для credential confirmation. System UI preview содержит быстрые настройки-переходы к настоящим страницам Android Settings. Домашний экран включает виджет даты, сетку приложений, собственные векторные иконки, док и Центр управления; после завершения мастера Android предлагает назначить GiggleOS основным домашним экраном. Центр уведомлений по явному разрешению показывает источник и время уведомления, не сохраняя его текст; нажатие открывает исходное приложение. Предпросмотр блокировки показывает до двух таких записей с учётом настройки приватности. Меню приложений показывает реальные установленные приложения, их иконки и поддерживает поиск. Отдельное приложение настроек содержит поиск по разделам, сохраняемые темы, цветовые палитры и выбор обоев экрана блокировки, а также передаёт защищённые параметры в системные экраны Android.

Эти прототипы не являются привилегированными компонентами AOSP. Они не заменяют системный Keyguard, notification shade или Quick Settings. Debug APK-прототип собирается через GitHub Actions; это не AOSP-сборка и не установочная прошивка.

## Поддержка устройств

Каждая модель требует собственной проверки загрузчика, разметки разделов, ядра, драйверов, vendor blobs и аппаратных функций. Новые устройства добавляются отдельными портами и проходят тестирование до публикации.

## Безопасность

- Не публиковать образы как стабильные, пока они не прошли проверку.
- Не использовать образ для другой модели или варианта устройства.
- Перед любыми экспериментами сохранить данные и иметь проверенный план восстановления.
- Не обходить блокировки и проверки совместимости установщика.

## Лицензии

GiggleOS будет включать компоненты AOSP и сторонние компоненты с разными лицензиями. Лицензии и уведомления каждого включённого компонента должны сохраняться; лицензию собственных файлов проекта нужно определить отдельно.
